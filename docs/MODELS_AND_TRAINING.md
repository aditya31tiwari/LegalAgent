# Models and training

All training ran on one laptop GPU (NVIDIA RTX 4050 Laptop, 6 GB) unless noted. Every number
quoted here is regenerated by `scripts/eval_all.py` into `results/` — see
`results/REPORT_TABLES.md` for the current values; this file explains *what* and *why*.

## 1. Clause classifier — CLAUSE-22 (multi-label)

| | |
|---|---|
| Model | `law-ai/InLegalBERT` (BERT-base pretrained on Indian court judgments), full fine-tune, sigmoid multi-label head |
| Data | CLAUSE-22: 55,915 train / 9,341 val / 8,415 test (LexGLUE official) / 703 test_ood (CUAD contracts never seen in training) |
| Recipe | `train/finetune_classifier.py`: 3 epochs, AdamW lr 3e-5, batch 16, max 256 tokens, fp16, linear warm-up 6 %, decision threshold tuned on validation only |
| Time | ~48 min (2,879 s) |
| Baselines | keyword rules; frozen MiniLM-L6 + one-vs-rest logistic regression (`clause20/train.py`) |
| Ablation | taxonomy v1 (CLAUSE-20, 20 labels) vs v2 (CLAUSE-22, + arbitration, remedies) — same recipe |

Result (test / test_ood micro-F1): MiniLM+LR (original report) 0.81 / 0.46 → InLegalBERT v1 0.925 / 0.715 →
**InLegalBERT v2 0.931 / 0.750**. Adding two labels *improved* out-of-distribution F1, because
the research-driven mapping also removed noisy rows (e.g. liquidated damages out of
`limitation_of_liability`, M&A boilerplate out of `compliance_and_law`).

On top of the model (documented, auditable, not counted in model metrics):
- **Keyword backstop** for indemnity / liability cap / restraint — the three types whose miss
  hides the flagship clashes. Added only when the model left the label out; tagged `keyword_backstop`.
- **7 Indian rule labels** (`known_gaps`: force majeure, liquidated damages, data protection,
  stamp duty, performance security, change in law, step-in rights) — no or too few gold rows in
  CUAD/LEDGAR, so detected by anchored keyword rules rather than faked with synthetic data.

## 2. Related-clause retriever — InLegal-SBERT, contrastive

| | |
|---|---|
| Model | `bhavyagiri/InLegal-Sbert` → `models/inlegal_sbert_clauses` |
| Data | 2,821 (clause, cross-referenced clause) pairs from CUAD contracts **outside** the retrieval evaluation set; text masked exactly as the retriever sees it (clause numbers and "Section x.y" removed) so the model cannot learn the citation itself |
| Loss | Cached Multiple-Negatives Ranking Loss (GradCache): batch 64 in-batch negatives computed in mini-batches of 8 (a plain batch-32 MNRL run went out of memory on 6 GB) |
| Why | Base InLegal-SBERT was the weakest retriever (trained on judgments, not contracts); BM25 beat all dense models on Indian concessions |

## 3. Pair judge — Kev-0.8B decision model (local)

| | |
|---|---|
| What Kev is | Open (Apache-2.0) reconstruction of TypeSafe's proprietary "Jev" System One decision model: frozen Qwen3.5-0.8B backbone + LoRA (r 16) + pointer head; reads a document and returns calibrated probabilities over the options of typed questions in **one forward pass, no text generation** |
| Our questions per pair | `relation` (choice: conflict / dependency / overlap / ambiguity / no_issue, each with a definition) · `severity` (score: low < medium < high) · `statute` (choice among the 4 India Code sections retrieved for that pair, or none) |
| Training data | teacher-labelled pairs (Section 5), split **by contract**; clause types re-computed with the current CLAUSE-22 classifier so training and inference see the same vocabulary |
| Recipe | `train/kev_pipeline.sh` → `kev.train --init_from jaredpalmer/kev-0.8b` (LoRA delta), lr 1e-4, 2 epochs, grad-accum 8, max state 1,536 tokens; served with `kev.serve` on 127.0.0.1:8008 (System One API) |
| Compared | rules · Kev base zero-shot · Kev fine-tuned · Gemini teacher (reference) — on held-out pairs, the known-answer checklist, and blind human labels |

## 4. Clause-graph GNN

GraphSAGE (2 layers, 128-d) over each contract's clause graph — nodes: MiniLM embedding ⊕
CLAUSE-22 multi-hot ⊕ position; edges: cross-references, parent/child, document order, 5-NN
similarity — with a pair scorer `MLP[h_a, h_b, |h_a−h_b|, h_a∘h_b, type-matrix weight]`
trained by BCE on teacher-labelled pairs (risky = relation ≠ no_issue), split by contract.
Ablations: the same scorer **without message passing**, type-matrix weight alone, cosine alone.
Used optionally as an extra shortlisting signal (`--gnn`).

## 5. Teacher (distillation source)

Gemini 4 Hydrogen (high) via the Antigravity CLI in non-interactive print mode with a JSON
schema (`scripts/label_with_agy.py`); 20 pairs per call; prompt = `research/teacher_labels/PROMPT.md`.
1,000 pairs labelled in priority order (all 123 Indian pairs, then cross-reference/type-matrix
pairs, then the rest) for ~44 % of one 5-hour quota window. Each label records model,
conversation id, batch, timestamp and token usage. Validation in `docs/EVALUATION.md`.

## Reproduce
```bash
for st in labels cuad ledgar merge dedup split; do venv/bin/python clause20/build.py $st; done
venv/bin/python train/finetune_classifier.py                       # classifier
venv/bin/python train/finetune_retriever.py clauses                # retriever
venv/bin/python scripts/build_judge_set.py import-labels           # teacher labels -> judge set
bash train/kev_pipeline.sh                                         # Kev train + eval + serve
venv/bin/python train/train_gnn.py                                 # GNN + ablations
for w in classifier retrieval statutes judge checklist e2e tables; do venv/bin/python scripts/eval_all.py $w; done
```
