  Inside the judge
  
Kev reads, then points at an answer

  
Kev-0.8B is a decision model: a small language model (Qwen3.5, 0.8 billion parameters) with a pointer head. It reads a "state" and a question with fixed options, and returns a probability for each option. It never writes free text, so it cannot invent a reason or a law. Below is the real request and response for Clause 91.3 (the Indian-law check).

How the card text is made

  Choosing which pairs to judge
  
From 14,025 possible pairs to 173

  
Judging every pair of a 580-clause contract would take hours. Three signals pick the pairs worth asking Kev about: cross-references ("subject to Clause 14.2", always kept), a 40-pair clash matrix of clause types (cap × indemnity weight 0.90), and hybrid search (BM25 keywords + dense meaning). The rest is ranked and capped at 60.

  Graph neural network · toy demonstration
  
GraphSAGE: a clause learns from its neighbours

  
Each clause is a node. Edges connect clauses that cite each other, a clause and its parent, neighbours in the document, and each clause's 5 most similar clauses. In one round of message passing every node replaces its vector with a mix of its own and the mean of its neighbours'. Two rounds means a clause "hears" from clauses two hops away. Below, each node carries one number (think "riskiness") instead of a 415-number vector, to show the mechanics.

  

    
Round 0

    

    
Toy rule here: new = 0.5 × own + 0.5 × mean(neighbours). Real GraphSAGE learns weight matrices for both parts, uses 2 layers with 128 hidden units, and then scores a pair from [h_a, h_b, |h_a−h_b|, h_a·h_b, clash weight].

  

  

    
Our result (172 held-out pairs)

    
Why the graph didn't help
The ablation trains the same scorer without message passing. It did as well (0.748 vs 0.742), so the graph structure added nothing measurable. Likely reasons: contracts have few cross-references per clause, so the graph is sparse; only 172 labelled test pairs; and the text embedding already carries most of the signal. The GNN is built, trained (19 min) and evaluated, but off by default.

  







  Retrieval-augmented grounding
  
Indian law is retrieved, never written from memory

  

    
How

      
library
4,408 India Code sections (ICA 201, A&C Act 102, Stamp Act 77, DPDP 45, Specific Relief 44, Companies 453, IBC 268 …) plus key Supreme Court precedents

      
search
BM25 + our fine-tuned InLegal-SBERT, fused with RRF, plus a small bonus for contract-related Acts

      
use
Kev chooses among 4 retrieved sections; every citation is checked to exist; each reference carries a confidence chip

    
Exact section in top 5 (19 independent queries)

      
Gold = the section a court applied, plus our planted faults. Fine-tuning the retriever (1.3 min on 2,967 pairs) brought 0.21 → 0.32. The reranker made it worse and needs GPU memory, so it is off.
