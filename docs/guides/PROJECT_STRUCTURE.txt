================================================================================
WHAT'S IMPLEMENTED (Days 1–8)
================================================================================

✓ Core Types       (Day 1–2)   core/types.py
  └─ Clause, Finding, Run — final shapes, mirrored in DB/API

✓ Ingestion        (Day 3–4)   core/ingestion.py
  └─ PDF/DOCX/TXT → normalized_text (canonical document)

✓ Extraction       (Day 5–6)   core/extraction.py
  └─ Regex-based clause splitting (decimal numbering: 5.2, 1.2.3)
  └─ Cross-reference detection (Section N.M → clause_id resolution)

✓ Classification   (Day 7)     core/classification.py
  └─ Keyword dictionary (substring match, case-insensitive)
  └─ Populates Clause.labels with confidence=1.0

✓ Candidate Select (Day 8)     core/candidate_selection.py
  └─ BM25 scoring (top-k similar clauses)
  └─ xref-based pairing (resolved cross-references)
  └─ Type matrix (label pairs that conflict)

✓ Pipeline         (Days 1–8)  core/pipeline.py
  └─ Orchestrates all layers: file → Run/Clauses/Findings

✓ CLI              (Days 1–12) __main__.py
  └─ python -m legalagent analyse contract.pdf

✓ Smoke Test       (Days 1–12) tests/test_pipeline.py
  └─ End-to-end validation: extraction → classification → candidates

================================================================================
HOW TO RUN
================================================================================

1. Setup:
   pip install pdfplumber python-docx

2. Smoke Test (validates all layers):
   python tests/test_pipeline.py

3. Analyze a Contract (CLI):
   python -m legalagent analyse tests/fixtures/sample.pdf
   python -m legalagent analyse contract.pdf --top-k 5 -o output.json

4. Output Format (JSON):
   {
     "run": {
       "id": "run_...",
       "contract_id": "...",
       "config": {"retrieval_method": "bm25", "top_k": 5},
       "stats": {"clauses": 47, "pairs": 28, "findings": 6, "no_issue": 22}
     },
     "items": [
       {
         "relation_type": "conflict",
         "severity": "high",
         "risk_score": 0.9,
         "target_clause": {"id": "...", "number": "5.2", "heading": "..."},
         "related_clauses": [{"id": "...", "number": "9.1", ...}],
         ...
       }
     ]
   }

================================================================================
DESIGN PRINCIPLES (Ponytail Mode)
================================================================================

1. Minimal Code: Fake stages in <50 lines if possible
2. Integration First: Surface structural problems early
3. Shapes Final: No renaming from v0 → product
4. Ingestion Perfect: char_start/char_end are precious
5. One Caller Per Stage: Each layer has one next layer
6. Testable: One smoke test validates the whole chain
