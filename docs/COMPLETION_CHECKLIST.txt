ARCHITECTURE DECISIONS (Ponytail Mode)
================================================================================

Decision 1: No LLM Analysis in v0
  Rationale: Integration matters more than accuracy
  Impact: All pairs return no_issue (0 findings)
  Upgrade: Day 9 adds Claude API call

Decision 2: Keyword Classification Only
  Rationale: 50 lines, fires type_matrix conflicts
  Confidence: 1.0 (keyword source, will be wrong)
  Upgrade: Week 5 adds LegalBERT model

Decision 3: Naive BM25 (TF-IDF)
  Rationale: Good enough for v0 integration problems
  Performance: O(n²), acceptable for ~50 clauses
  Upgrade: Week 6 adds dense + hybrid retrieval

Decision 4: Type Matrix (Simple YAML)
  Rationale: 20 lines, defines label pair conflicts
  Persistence: Survives unchanged to v1
  Use: Drives candidate generation

Decision 5: No Database
  Rationale: JSON on disk is complete deliverable
  Benefit: Shapes are final, no schema redesign
  Upgrade: Week 11 adds PostgreSQL

Decision 6: Single Smoke Test (No Unit Tests)
  Rationale: YAGNI — one integration test catches breakage
  Coverage: Validates all layers end-to-end
  Approach: Fail-closed (asserts stop on breakage)
